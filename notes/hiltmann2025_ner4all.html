Hiltmann 2025_NER4all：把歷史脈絡寫進 prompt 就能做好 NER

來源 extract_ohistory/refs/notes/hiltmann2025_ner4all.md　來源最後修改 2026-07-22　分類 ④ 口述歷史與數位人文　問題 ④　原文 PDF

  • 完整書目：Hiltmann, T., Dröge, M., Dresselhaus, N., Grallert, T., Althage, M., Bayer, P., Eckenstaler, S., Mendi, K., Schmitz, J. M., Schneider, P., Sczeponik, W., & Skibba, A. (2025). NER4all or Context is All You Need: Using LLMs for Low-Effort, High-Performance NER on Historical Texts. A Humanities Informed Approach. arXiv:2502.04351v1 [cs.CL], 2025-01-30。預印本，未經同儕審查。
  • 對應待查問題：④口述歷史／數位人文（附帶觸及 ⑤無 gold standard 評估的反面：本篇其實是有 gold standard 的一方）
  • 一句話定位：這篇用一份 1921 年柏林旅遊指南當實驗場，證明只要把歷史脈絡與人物角色（persona）寫進 prompt，市售 LLM（GPT-4o）不必微調就能在命名實體辨識（NER）上勝過 spaCy、flair 這類傳統工具；它是「把領域知識寫進 context 就能拉高效能」這個主張最直接、最完整的實證，正好替本專案用 skill 檔案承載領域判準的做法背書。

1. 貢獻

這篇的核心主張只有一句話：NER 不該被當成純語言學任務，而該被重新想成一件需要領域知識的人文工作。作者（多為 Humboldt 大學歷史學者，掛在 NFDI4Memory 與 AI-Skills 計畫下）論證，歷史文本之所以難做 NER，不是因為 LLM 語言能力不足，而是因為判斷「這串字是不是、是哪一類實體」本來就需要對時代、地方、社會慣例的背景知識，而這些知識其實已經藏在 LLM 的訓練資料裡，只等著被 prompt 喚醒（作者用的詞是 activate the embedded knowledge）。

具體貢獻有三：

  1. 提出一套「人文學者導向」（humanities informed）的 prompt 設計，把歷史脈絡與角色設定當成主角，而非把力氣花在調輸出格式或堆範例。
  2. 用嚴謹的實驗（含 ablation study 消融研究，即逐一關掉 prompt 的某個零件看效能掉多少）拆解出：真正拉高效能的是「脈絡」，不是常見的 prompt engineering 技巧。
  3. 提出一個政治性的目標，作者稱之為 democratize（讓人人可用）：既然只要寫自然語言 prompt，不必寫程式、不必準備訓練資料，歷史學者就能自己做高品質 NER，不再被 NLP 工具的技術門檻擋在外面。

值得注意的是，作者刻意不提出一套固定的 prompt 範本當標準答案。他們明說這是個變動極快的領域，重點是「領域與素材特定的脈絡資訊很重要」這個論點本身，而非任何一組具體指令。

2. 知識怎麼被萃取（抽取流程）

先講清楚範圍：這篇做的是 NER，只到「找出並分類」為止。實體的消歧（同名不同人）與連結（linking 到權威檔）作者明確排除在外，說那是後續兩個獨立步驟。所以它不建知識圖譜、不抽事件與關係，就是在一段文字裡把人、組織、地方標出來。

輸入是一頁一頁的歷史文本（每頁約 4000–9000 字元）。整個做法是單次抽取、單一 LLM、零額外訓練，沒有多 agent 分工，也沒有多步驟串接。流程可以拆成三段白話：

  1. 輸入準備：把 1921 年的紙本指南掃描、用 OCR4all 做文字辨識（字元錯誤率 CER 只有 0.0064，等於幾乎沒錯），再做最小的前處理（去掉換行、斷字連字號、正規化空白），用 spaCy 斷詞。
  2. 餵一個精心設計的 prompt 給 GPT-4o（gpt4o-2024-08-06），要求它把整段文字原封不動地重抄一遍，同時在實體前後插入標籤（見第 4 節的標籤格式）。要求原文照抄是為了不讓模型偷改、漏字。
  3. 後處理對位：因為 LLM 生成常常不完全逐字（會自己「訂正」原文、改連字號），輸出的實體片段不見得能在原文精確找到。作者用 fuzzysearch 套件的 find_near_matches 做模糊比對，容忍每 5 個字元 1 個錯（Levenshtein 距離），把生成的標記片段定位回原文。作者說這樣定位「零失誤」。

整個抽取只有這一趟。所謂的「方法」複雜度全部集中在 prompt 怎麼寫，而不在流程架構。

3. 知識怎麼被組織（結構與屬性）

實體類別只有三種，刻意壓到最小：PER（人）、ORG（組織）、LOC（地方）。這裡有一些人文判斷寫進了定義，值得記：

  • PER 包含在世者、歷史人物、神話人物，也包含「靠個別成員定義的集體」，例如藝術團體 Die Brücke。但頭銜、稱謂、地址（如 geh[eimer] Regierungsrat）不算 PER。
  • ORG 指法人化的集體：公司、公共機構、協會等。
  • LOC 指地理位置。
  • 遇到「本身有實體地點的組織」（餐廳、甚至一座城市），到底標 ORG 還是 LOC，看脈絡：文字若強調方位（如指路）就標 LOC，否則標 ORG。餐廳一律當 ORG，即使名字看起來像人名。

這套判準不是作者憑空發明，而是沿用 Impresso 計畫的 NER 指南（Ehrmann et al. 2020）改寫。不允許巢狀標註（nested annotation），也就是一個實體裡不再標更小的實體。

關鍵：這篇沒有跨文件去重、沒有實體合併、沒有衝突解決，因為它根本不做消歧。組織層次就停在「單頁之內、把 span 標出並歸類」。沒有任何「重新安排既有結構」的融合或精煉步驟。這是它跟知識圖譜類研究最大的不同，也正好對照出本專案（要跨訪談合併實體）多出來的那一大塊工作，這篇完全沒碰。

4. 表示法：是不是三元組？

不是三元組，是「行內標籤標註的字元片段」（span-based, tag-like annotation）。作者受 Wang et al. (2023) 啟發，最後選定的格式是：

<<TAG word word word /TAG>>

例如 <<PER Aves /PER>>、<<LOC Garetien /LOC>>。用 << >> 包住、TAG 是 PER/LOC/ORG。作者發現用這種「像標記語言」的格式，比要求模型「逐詞輸出語意標籤」穩定得多，連小模型都幾乎不會生成多餘空格或標籤開合錯誤。他們推測原因是訓練資料裡有大量結構近似的東西（程式碼、HTML、數學），模型對這種格式很熟。這也讓 prompt 不必浪費篇幅去教格式。這格式能表達巢狀（標籤可重疊），但本實驗禁用巢狀。

關於本專案最在意的三個欄位：

  • 出處（provenance）：沒有。標籤直接嵌在被抄回的原文裡，靠「片段在哪一頁原文的哪個位置」隱含地當出處，但沒有結構化的出處欄位。這跟本專案「每筆強制附檔名、時間碼、口述者、段落」的要求距離很遠。
  • 時間資訊：沒有。實體不帶時間屬性。
  • 信心分數：沒有讓模型自評信心。評估是拿模型輸出跟人工標準答案比，算出 P/R/F1，信心的概念不進入表示法。

換句話說，這篇的表示法比本專案簡單很多：它只需要「標出來、歸類」，不需要承載出處、時間、關係、評價。它選標籤格式純粹是為了 LLM 生成穩定與後處理好對位，不是為了知識表示的豐富度。

5. 資料集

  • 語料：一本書——Baedeker 出版的《柏林及周邊：旅人手冊》第 19 版（Baedeker & Graupe 1921），德文。選它的理由：有清楚的歷史脈絡（1920 年前後柏林旅遊資訊）、部分用當時的語言、而且結構多變（從敘述段落到公車路線清單都有），實體密度高、種類雜，適合當 NER 的壓力測試。
  • 語言：德文為主，prompt 另做了英文版對照。完全沒有中文（正文提到別人做過古典中文的研究 Tang et al. 2024，但本篇自己不碰中文）。
  • 規模：人工標註 55 頁（隨機選），其中 25 頁拿來評估，全語料共 1490 筆標註。這規模不大。
  • 領域：歷史文本、旅遊指南，屬印刷體、書面語。不是口語、不是訪談——這點跟本專案的口述歷史逐字稿差別很大。
  • 公開性：作者宣稱資料與程式碼都用開放授權放在 OSF（連結在論文裡，匿名審查用）。這是自建資料，不是既有 benchmark。作者刻意不用現成 benchmark，理由是他們要用自己有把握的歷史脈絡當領域知識來源。
  • 有沒有提出新 benchmark：算是提供了一份新的標註資料，但作者沒把它包裝成通用 benchmark，定位是「這一份素材上的實驗」。

6. 評估

有 gold standard，而且是紮實的人工標註：55 頁由兩位團隊成員各自獨立用 INCEpTION 工具標，標不一致的地方由第三人裁決。這是傳統、正規的標註流程。

  • 指標：precision（精確率）、recall（召回率）、F1。作者特別強調歷史學者「重召回勝過精確」——寧可多抓一些讓人事後刪，也不要漏掉。所以雖然報三個數字，論述重心放在召回。
  • 比對方式：用 nervaluate 套件，採最寬鬆的 ent_type 準則——只要生成 span 跟標準答案有重疊、且類別對，就算命中（Segura-Bedmar et al. 2013）。因為是按頁標註，所有數字都報「每頁的平均值 ± 標準差」。
  • 有沒有用 LLM 自評或 LLM 當評審：都沒有。信心分數不讓模型給；評分是拿模型輸出對人工答案算 P/R/F1，不存在「用 LLM 驗證 LLM」的循環。這點在方法論上很乾淨，正好符合本專案「絕不叫 LLM 自評、也不搞 LLM 循環自證」的紅線。
  • 人工介入程度：介入在「建標準答案」與「寫 prompt 裡的脈絡」兩處，都是人做；抽取本身全自動。few-shot 用的範例也要人工標（200–500 字元的小片段），作者說這很花人力，也是他們論證「零範例其實夠用」的動機之一。

主要數字（都以 F1 為主軸）：

  • 傳統工具基線：flair（ner-german-large 模型）F1 0.81（召回 0.76、精確 0.89）；spaCy（de_core_news_lg）慘，F1 只有 0.50（召回 0.59、精確 0.44），ORG 召回只有 0.12，還把 684 個非實體誤標成實體。
  • 完整 prompt 的 GPT-4o：德文 F1 0.87、英文 F1 0.88。
  • 換算成領先幅度：召回比 flair 高約 10%、比 spaCy 高約 15%；F1 比 flair 高約 7%、比 spaCy 高約 22%。
  • 脈絡的效果（0-shot 條件下逐層加脈絡）：無脈絡 → 加通用歷史學者角色（generic persona），召回約 +6%；再加素材特定的細節（specific context），召回再 +5%。這是全篇最重要的一組對照。
  • prompt engineering 技巧的效果很小：消融研究顯示 structure（加 markdown 分區標題）、instruction-repetition（結尾重述指令）、bullying（給獎懲，即所謂「賄賂」模型）、system-prompt（把指令與資料拆成 system／user 兩則訊息）這些常見技巧，各自只帶來 1–2% 上下的變動，而且跟脈絡不是單純相加——作者說兩者「交纏」（intertwine），把技巧全開並不保證更好（No Context 加不加 PE 幾乎沒差）。
  • few-shot 反而不如 zero-shot：出乎作者預期，0-shot 在召回與精確都比 few-shot 好，要到 16-shot 以上才看到一點點改善，且 32-shot 仍未觸及召回天花板（受限於 context window 塞不下更多）。結論：花人力準備範例不划算。
  • 語言：英文 prompt 原本召回比德文高約 5%，但把簡單的 prompt engineering 技巧加上去後，德英差距就變得不顯著。作者據此說這個方法對非英語社群也可用。

一個很漂亮的案例：標註 "Borstells Lesezirkel"（Borstell 的讀書會／租書社）時，兩位人工標註者把 "Borstells" 標成人名（PER），模型卻正確判斷整串是一個組織（ORG）——因為那其實是一家商業租書店，這個事實人工標註者不知道，但藏在模型的知識庫裡。作者用這個例子說模型在「它所涵蓋的知識範圍內」可以像一位「全知的歷史學家」勝過人類標註者。這個案例也被作者當成「未來可用模型輔助反覆修正 gold standard」的線索。

7. 發現的問題與限制

作者自己承認的：

  • 領域變動太快，實驗只能反映當下狀態；不同 LLM 表現會不同，他們不敢提出定版的 prompt 標準。
  • 效能不能歸功於「模型語言理解更靈活」——他們指出無脈絡時模型 F1（0.81）跟 flair 一模一樣，差別完全來自脈絡。這其實是誠實但也削弱了「LLM 本身多強」的說法。
  • 模型受限於自身的偏誤與訓練資料涵蓋範圍，「全知歷史學家」只在它知道的範圍內成立。
  • 未來工作坦承還沒處理：更早期的語言形式、獨特的自訂類別、讓模型自己找出文本特性來生成脈絡、以及歷史文本本身的模糊性怎麼在評估裡表現。

我讀出來、它沒講清楚或該存疑的地方：

  • 樣本太小：25 頁、1490 筆標註、單一本書、單一語言家族（德／英）。「context is all you need」這種大標題，證據基礎其實相當窄。所謂 16th–18th 世紀的可遷移性只是 preliminary test，沒給數字。
  • 它做的是最簡單的 NER：三類、不巢狀、不消歧、不連結。它證明的是「脈絡幫助分類與召回」，不能直接推論到本專案要的關係抽取、事件抽取、跨文件合併——那些任務的難度與錯誤模式完全不同。
  • 評估用最寬鬆的比對準則（overlap + 類別對即算命中）。這對召回導向的歷史學者合理，但會讓 F1 看起來比嚴格邊界比對漂亮，跟其他論文的數字不能直接比。
  • 「democratize」的說法有張力：一方面說人人可用自然語言、免寫程式；另一方面整條管線其實包含 OCR4all、自訓辨識模型、spaCy 斷詞、fuzzysearch、nervaluate 這些要寫程式的環節。真正「免程式」的只有 prompt 那一層，論文對此不夠誠實。
  • 成本與封閉模型依賴：用的是商用 API（GPT-4o），脈絡越長、輸入越大，token 成本越高，且結果依賴一個黑箱、不可獨立驗證、會隨版本改變的模型。對要求「可追溯、可重現」的歷史研究是隱憂，作者只在註腳輕輕帶過。

8. 對 extract_ohistory 的啟示

這篇是本專案方法論最直接的外部背書，但要小心它證明的範圍比標題小。

可以借用、且和本專案高度相容的：

  1. 核心論點就是本專案的做法：把領域知識（歷史脈絡、人物角色、素材特性）寫進 prompt，效能就上得去，不必微調。本專案用 srt-extract 的 criteria.md、用 skill 檔案承載「使用者審訂的判準」，正是同一個思路的工程化版本——把 Impresso 式的標註指南搬進 skill，讓判準以自然語言脈絡的形式驅動抽取。這篇替「skill 檔案 = 可運作的領域脈絡」提供了量化證據（脈絡帶來 +11% 召回，遠大於花俏技巧的 1–2%）。
  2. zero-shot 勝 few-shot 的發現值得記：範例要人工標、很貴，而且 16-shot 以下反而拖累。本專案若考慮在 skill 裡塞抽取範例，這篇提醒範例的邊際效益低、成本高，不如把力氣花在把脈絡與判準寫清楚。
  3. 不叫 LLM 自評、不搞 LLM 循環自證：這篇評估乾淨地用人工 gold standard 對 P/R/F1，沒有 LLM-as-judge，完全吻合本專案第 2 條紅線。可當作「正規評估該長什麼樣」的參照。
  4. prompt engineering 技巧（獎懲、重述、深呼吸咒語）效果很小且與脈絡交纏：這對本專案是個警訊——不要迷信那些江湖技巧，該投資的是脈絡與判準的正確性。

該避免、或這篇幫不上忙的地方：

  1. 出處：這篇沒有出處欄位，靠標籤嵌回原文隱含定位。這跟本專案第 3 條紅線（每筆強制附檔名、時間碼、口述者、段落）正面衝突，不能照抄。本專案要的是結構化出處，這篇的行內標籤法不適用。它的模糊比對（fuzzysearch 把生成片段定位回原文）倒是有參考價值：LLM 抽取常不逐字，本專案若要把抽出的內容對回 SRT 的時間碼段落，這種「容錯定位」技巧可以借。
  2. 表示法太薄：只有 span 標籤、三個類別、不巢狀、無時間、無關係、無 goût 評價。本專案的實體／事件／關係／goût 混合結構遠比它複雜，這篇在「知識怎麼組織」上幾乎沒有可搬的東西。
  3. 它不做消歧與合併：本專案最重的跨訪談實體消歧、合併、衝突解決，這篇明確排除。所以在 entity-resolve 這一層，這篇提供不了方法，只能說明「連分類都需要脈絡，消歧只會更需要」。
  4. 語料性質不同：印刷體書面語 vs 口語逐字稿。口述歷史有口誤、跳接、指代不清、時間錯置，這篇的乾淨旅遊指南沒這些問題，它的高分不能直接套用到 SRT 上的預期。
  5. 無 gold standard 的部分它幫不上：這篇是「有 gold standard」的一方。本專案事件層與關係層沒有 gold standard，這篇沒有處理「無標準答案怎麼評估」的方法，反而提醒我們：實體層本專案有人工名冊（entity_stage1_final.csv）可對照，這一層可以學這篇的正規 P/R/F1 評估；事件與關係層則要另想辦法（這篇沒答案）。

一句話總結給人文學者讀者：這篇證明了「你把知道的歷史背景好好寫給模型聽，它就做得比不懂歷史的工具好」，這正當化了本專案「用 skill 檔案把領域判準交給模型」的整個設計；但它只做到「標出實體」這一小步，本專案真正困難的出處綁定、跨訪談合併、事件與關係、以及口語文本的雜訊，都得靠自己解，這篇給不了現成答案。
