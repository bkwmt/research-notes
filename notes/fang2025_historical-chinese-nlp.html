Fang 2025_歷史中文 NLP：LLM vs 傳統工具在斷詞／詞性／NER 的比較

來源 extract_ohistory/refs/notes/fang2025_historical-chinese-nlp.md　來源最後修改 2026-07-22　分類 文獻深讀筆記（八節）

  • 完整書目：Fang, Z., Wu, L.-C., Kong, X., & Stewart, S. D. 2025. A Comparative Analysis of Word Segmentation, Part-of-Speech Tagging, and Named Entity Recognition for Historical Chinese Sources, 1900–1950. arXiv:2503.19844（v1, 2025-03-25）。預印本，未經同儕審查。
  • 對應待查問題：④口述歷史／數位人文（兼涉 ①LLM 抽取現況、⑤無 gold standard 評估的反面對照）
  • 一句話定位：這篇拿 1900–1950 年上海圖書館「民國期刊語料」的繁體中文史料，把六種傳統中文 NLP 工具和七款 LLM 放在斷詞、詞性標註、命名實體辨識三個任務上正面對打，結論是 LLM 全面勝出但成本高得多。它直接回答了本專案最關心的問題：拿現成 LLM 處理年代久遠、用語變動的中文文本，到底靠不靠得住。

1. 貢獻

這是一篇「短論文」（short paper），沒有提出新模型，貢獻在於一份針對過渡期（transitional-era）中文的 out-of-the-box 工具對照實驗。過去大家知道神經網路做 NER 比舊方法好，但對「歷史中文」這種低資源、用字與斷詞習慣都跟現代不同的材料，效果如何一直沒有系統性比較。作者建了一份人工標註的小型 ground truth，把 jieba、spaCy 系列這類傳統工具，跟 GPT、Claude、GLM 三家 LLM，在同一批史料上用相同的評估指標比出高下，並額外拆解了兩個變因：詩歌 vs 非詩歌、1920 年前 vs 1920 年後。核心結論：LLM 在三個任務全部指標上都贏傳統工具（僅一個例外），代價是運算成本與時間大幅增加；且 LLM 對文體差異（如詩歌）和跨年代的用語變化更有韌性，暗示它的脈絡學習能力可以「減少對特定領域訓練資料的依賴」。

2. 知識怎麼被萃取（抽取流程）

這篇不是「抽取結構化知識」，而是做語言學層次的逐字標註：把一段古早中文切成詞（斷詞）、給每個詞標詞性、標出是不是命名實體。流程單純，是單次呼叫、沒有多步或多 agent 分工：

  1. 給每個工具／模型餵同一段原文。
  2. 傳統工具（jieba、spaCy）直接跑出斷詞與標註。
  3. LLM 則靠一則統一的 prompt。prompt 內容值得記：它要 LLM 扮演「處理 1900–1950 繁體中文的 spaCy 風格標註器」，明確要求不得刪改任何文字（含標點與括號）、空格不算 token，三個子任務（切 token、標 coarse POS、標 entity）一次做完，並規定輸出成 JSON 物件陣列，還附了一個 input/output 範例（few-shot 示範格式，但非 few-shot 教學）。這對本專案是有用的 prompt 工程參考：把「忠於原文、不腦補、輸出結構固定」寫死在指令裡。

值得注意的是他們刻意用 out-of-the-box（開箱即用），不做微調（fine-tuning）也不做 few-shot 示例教學，就是要測「現成能力」。

3. 知識怎麼被組織（結構與屬性）

組織方式極簡：每個 token 一個物件，欄位只有三個──text（原字串）、pos（粗粒度詞性標籤）、ent（若屬於某命名實體則標其類型，否則空字串）。沒有 schema／本體（ontology）意義上的實體型別階層，也沒有跨文件去重、實體合併、衝突解決。因為任務停在「單篇、單句、逐 token」的層次，根本不進到跨文本的實體整併。所以這篇對本專案「跨訪談消歧、合併決策」那一層沒有直接可借的做法——它處理的是比抽取更前端的問題（先把字切對、標對）。

一個對本專案有啟發的討論點在第 4 節與結論：作者坦承歷史中文沒有唯一正確的斷詞方式。舉例「上海圖書館」該當一個 token 還是切成「上海／圖書館」，取決於研究問題；「教授」在 1920 年代已是「professor」的單一詞彙，但在古典中文裡是「傳授知識」兩個動作，切法隨語意與時代而變。這說明實體邊界本身帶有詮釋性、隨研究目的浮動——正呼應本專案「實體是人工判斷、非機械對齊」的立場。

4. 表示法：是不是三元組？

不是三元組。用的是逐 token 的屬性標註（token-level tagging），輸出為 JSON 物件陣列，每個物件是 {text, pos, ent} 的扁平結構。沒有主謂賓關係、沒有事件框架、沒有屬性圖。

關鍵缺口（對本專案而言）：沒有出處（provenance）欄位、沒有時間資訊欄位、沒有信心分數。這很合理，因為它的評估對象是「切得對不對、標得準不準」，出處就是那一篇 passage 本身，不需要在資料結構裡再帶。信心分數方面，這篇完全沒有叫 LLM 自評信心，好壞全靠對照人工答案算出來——這一點與本專案紅線 2（絕不叫 LLM 自評信心）方向一致，可當正面案例引用。

5. 資料集

  • 語料：上海圖書館「民國期刊語料庫」（Shanghai Library Republican Journal corpus），晚清與民國時期的期刊。公開資料集（來源網址見論文註腳，芝加哥大學 Textual Optics Lab 託管）。
  • 語言：繁體中文（LLM prompt 明寫 Traditional Chinese），正是本專案語料的同一書寫系統，這是這篇對我們特別相關的原因。
  • 規模：小。從語料中抽 208 段（passages），涵蓋 1900–1950；其中 41 段為詩歌，其餘 167 段非詩歌，分佈於五個十年：1900(23)、1910(32)、1920(40)、1930(34)、1940(38)。每段 6–170 字，平均 41.3 字，總計 8,610 字。（Limitations 另述：初版 100 段，後補 100 段以測穩健性，數量與正文 208 略有出入。）
  • 領域：多文體的書面史料（政府報告、學術寫作、社會政治評論、短篇小說、詩歌）。沒有口語、沒有訪談、沒有語音辨識文本——這是它與本專案的最大落差：我們的材料是口述歷史 SRT 逐字稿，含口語、停頓、ASR 錯字。
  • 新 benchmark？：算是提出了一份新的人工標註評估集（斷詞／POS／NER 三層），但規模很小、且似乎未見公開釋出標註檔，主要作內部對照用。

6. 評估

  • 有人工 gold standard：作者群集體斷詞與標註，每段由兩位作者交叉核對，歧異經討論後解決。這是紮實但成本高的小規模人工標準答案。
  • 指標：斷詞用 F1（平衡過度切分與切分不足，論文採「F1 ≥ 90% 視為高準確」的慣例門檻）；詞性與 NER 用準確率（accuracy %）；另記錄處理時間（秒）、送出／接收 token 數、以及 LLM 回傳失敗次數。
  • 一個評估設計的隱藏前提要留意：POS 與 NER 的準確率是只在「已正確斷詞的 token」上計算。也就是說 NER 分數是條件於斷詞正確的，斷詞先錯的部分不進 NER 分母。這會讓斷詞差的工具在 NER 上的數字看起來不那麼難看，跨工具比較時要小心解讀。
  • 有沒有用 LLM 自評／LLM 當評審（LLM-as-a-judge）？沒有。 全部對照人工答案計分，沒有循環自證的問題。這點乾淨。
  • 人工介入程度：集中在前端建 ground truth（雙人標註＋討論），評估本身是程式化比對，無事後人工調分。

主要數字（節錄 Table 1，全語料）：傳統工具中 spacy_bert 最好（斷詞 F1 82.50、NER 93.78）；LLM 中 o3-mini 最強（F1 94.50、POS 88.83、NER 97.00）但耗時 5295 秒、接收 token 逾 70 萬，成本高到不切實際；gpt-4o（F1 91.97、NER 96.40，797 秒）與 claude-3-5-sonnet（F1 93.41、NER 94.24，1486 秒）在準確與速度間最平衡；claude-3-5-haiku 有 13 次未依格式回傳（失敗最多）；GLM-4 系列墊底，GLM-4-Long 的 NER 甚至輸給傳統工具。

7. 發現的問題與限制

論文自己承認的： - ground truth 樣本小（百餘至兩百段），雖加倍後結論未變，仍需更大資料集驗證。 - 只測 out-of-the-box，未試微調或 few-shot，未必是各工具的上限表現。 - 未來想做開源模型以兼顧可擴充性、效率與可近用性。

我讀出來、它沒明講或值得存疑的： - POS 準確率對傳統工具可能不公平。jieba 全語料 POS 只有 42%，低得異常，很可能是傳統工具的詞性標籤集與作者採用的 coarse 標籤集對應不上（標籤 mapping 損失），而非真的「標錯」。這種標籤體系落差會系統性壓低傳統工具的分數，論文沒有交代標籤對齊怎麼處理。 - NER「準確率」的定義偏窄：如上所述只算已正確斷詞的 token，且用的是 accuracy 而非 NER 慣用的實體級 P/R/F1，跨研究可比性打折。 - 成本結論被 o3-mini 一個極端點放大：把「LLM 成本高」寫得很重，但 gpt-4o-mini 之類便宜模型其實表現也不差，成本／效益的細緻取捨談得不夠。 - 樣本每段平均僅 41 字，偏短；長文本的斷詞錯誤累積效應未測。 - 繁體、書面、期刊——與口語、ASR 文本的落差完全沒觸及，卻在結論做了頗大的一般化（「推進中文 NLP」）。

8. 對 extract_ohistory 的啟示

最直接的佐證：這是目前少見、專門在繁體中文＋年代久遠（1900–1950）＋用語劇烈變動的材料上，實測現成 LLM 的研究。它的核心發現對本專案是強支持——現成 LLM（gpt-4o、claude-3-5-sonnet 這一級）在歷史中文的斷詞與 NER 上穩定勝過 jieba／spaCy，而且對跨年代用語變化與文體差異更有韌性（Table 3：傳統工具 1920 年前後 F1 差距大，約 77 → 90；LLM 差距小很多）。這正好回應本專案要處理跨越數十年、受訪者口中夾雜舊稱謂與時代用語的擔憂：LLM 的脈絡學習讓我們比較不必為「時代用語」另建詞典或做領域微調。claude-3-5-sonnet「跨所有類別結果一致且優異」的評語，也支持本專案以 Claude 為抽取主力的選型。

同時是警告： 1. 這篇證明的是「切詞、標詞性、辨識實體型別」這種前端語言處理，不是本專案要的「事件、關係、goût 敘述＋出處」那種結構化知識抽取。它的成功不能直接外推到我們更複雜的 schema。 2. 它的材料是乾淨的書面期刊，我們的是口述 SRT、含 ASR 錯字與口語。論文完全沒碰語音辨識錯字這一層；換句話說，關於「錯字容忍度」我們得自己驗，不能拿這篇背書。可預期的風險是：ASR 把人名、專有名詞打錯時，NER 會連帶失準，而這篇的高 NER 分數是在無錯字前提下取得的。 3. 連 claude-3-5-haiku 都會出現 13 次不依 JSON 格式回傳、GLM 系列大量失敗——提醒本專案在 headless 批次階段必須有格式驗證與重試機制（本專案 extract-qa 的出處存在性、格式合規檢查正對應這點）。

與四條方法論紅線的相容性： - 紅線 2（不叫 LLM 自評信心）：相容且是正面示範。這篇全程用人工答案計分，未用 LLM 自評。 - 紅線 1（不做配對式 gold standard）：部分張力，但性質不同。這篇有人工 gold（雙人標註），但那是 token 級的語言學標註，成本可控、學界慣例明確；本專案拒絕的是「抽取／消歧結果的 cluster 配對式 gold」，兩者不是同一件事。可借鑑之處：本專案實體層本就有人工名冊當對照，與這篇的 token 級 gold 精神一致——在「客觀有標準答案」的層次上用人工 gold 是可接受的，紅線針對的是主觀、配對式的消歧標註。 - 紅線 3（強制附出處）：這篇沒有出處欄位設計可借，因為它任務層次不到跨文本。本專案的出處需求仍要自己扛。 - 紅線 4（可追溯）：這篇是單次呼叫、無中間產物，也無可借鑑的落檔設計。

表示法層面的參考價值：有限。它的 {text, pos, ent} 扁平 token 結構與本專案「實體／事件／關係／goût＋出處」的混合結構差距很大，不是三元組也不是我們要的框架。但它的 prompt 設計哲學（明令不刪改原文、不腦補、輸出固定 JSON、附範例）值得直接沿用到 srt-extract 的指令裡，尤其「Do not remove any text」這種對抗 LLM 自作主張的護欄，與本專案「寧多勿漏、忠於原文」的詳細抽取原則同向。
