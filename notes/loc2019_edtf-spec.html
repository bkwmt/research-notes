這份文獻說了什麼

EDTF（Extended Date/Time Format）是美國國會圖書館帶著書目社群制定的日期表示 標準，解決 ISO 8601 原版說不出口的三類話：「大約某年」「不確定是不是某年」 「某年代的某時」。它分三個層級：Level 0 就是 ISO 8601-1 的基本日期與區間； Level 1 加上三個修飾符（? 不確定、~ 約略、% 兩者兼具，一律放字串尾端、 及於整個日期）、未指明數字 X（限最右側，如 196X＝1960 年代）、開放或未知 端點的區間（1985/..、/1985）；Level 2 允許 X 在任何位置、修飾符只管個別 成分，並新增集合表示（[1964..1966]＝這幾年中的某一年）。

三個查證點的答案： 1. 「1960 年代」＝ 196X（Level 1）；「約 1955」＝ 1955~（Level 1）； 「1964 到 1966 之間」＝ 1964/1966（Level 0 區間）。但注意 1964/1966 的語意是「一段期間」，若要說「單一事件發生在其中某一年」，Level 2 的 [1964..1966] 才是準確寫法——這個語意差在抽取口述時間時會真的遇到。 2. EDTF 確實已併入 ISO 8601 的 2019 年改版：LOC 背景頁明言 "EDTF functionality has now been integrated into ISO 8601-2019"；規格本文說 Level 1、2 對應 ISO 8601-2 的特徵。ISO 8601-2:2019 出版於 2019 年 2 月（付費標準，未取得）。 3. ? 與 ~ 的區分：? 是「不確定是不是這個值」（epistemic 的猶疑）， ~ 是「值是約略的」（精度問題），同時成立用 %。2012 草案的 u（未指明） 與 ?~ 連用已廢，讀舊文獻或舊程式庫要留意。

與本專案設計的對照

  • 「加不改」原則完全可行：EDTF 欄位可由程式從現行記法轉出，原記法保留。 同實驗室 NTU-Bonn 計畫的 mecad_sandbox/src/dates.py 已示範這條路： ParsedDate 同時保留 raw（原字串）與 edtf（轉出值）。
  • dates.py 實作了哪個子集（搬用前的盤點）：
  • Level 0 全部用上：單一日期三種精度、起/訖 區間（含 1987/88 展開為 1987/1988）。
  • Level 1 只用了一項：~（c. 1920 → 1920~）。
  • 年代（1930s）沒有用 EDTF 的 193X，而是轉成 Level 0 區間 1930/1939，再用自己的 precision="decade" 欄位補記精度。這對它的 時間軸繪圖夠用，但「十年精度」這個資訊被移出了 EDTF 字串本身。
  • 完全沒碰：?、%、未指明數字 X、開放／未知端點區間（..）、季節、 Level 2 全部（成分修飾、集合表示、有效位數）。
  • 另有兩個非 EDTF 的實用設計值得一併搬：精度排序（確切日期永遠勝過裸年份） 與「緊接左括號的年份跳過」（避開生卒年誤抓）。
  • 本專案的建議映射（口述語料的常見樣貌 → EDTF）：
  • 「六〇年代」→ 196X（直接用 Level 1 寫法，不必學 dates.py 轉區間； 本專案只加一個 EDTF 欄位，讓字串自足比較乾淨）。
  • 「大概民國五十幾年」→ 年代約略，195X 已表達「不知哪一年」；若口述者 連年代都拿不準可再加 ~（Level 2 才允許 195X~ 這種組合，採用前要決定 支援層級）。
  • 「好像是 1964 還是 65」→ [1964,1965]（Level 2 擇一集合）或退而求其次 1964/1965 區間加註。
  • 「明白承認不知道時間」→ 區間開放端點（../1970、1955/..）或乾脆 不填 EDTF、只留來歷標記，避免假精度。
  • 層次不要混：EDTF 的 ?／~ 只管「時間值本身」的不確定；ICCCM 摘要 承諾的 epistemic-status marker 管的是「這筆知識怎麼來」（親歷／轉述／ 承認不知）。兩者互補、不可互相替代：口述者親歷但記不清年份（來歷可靠＋ 時間 ~）與轉述者講了一個精確年份（來歷存疑＋時間無修飾）是完全不同的 證據樣貌，正好需要兩個欄位各自編碼。
  • 與紅線相容：EDTF 轉換是純程式規則（正則＋映射），不涉 LLM 自評，轉換 規則與原字串都落檔即可追溯。
