Rasmussen 2025_Zep：時序知識圖譜當 agent 的記憶層

來源 extract_ohistory/refs/notes/rasmussen2025_zep-temporal-kg.md　來源最後修改 2026-09-08　分類 ⑧ 本體學習與 schema 歸納　問題 ⑧⑥　原文 PDF

  • 完整書目：Rasmussen, P., Paliychuk, P., Beauvais, T., Ryan, J., & Chalef, D. (2025). Zep: A Temporal Knowledge Graph Architecture for Agent Memory. arXiv:2501.13956v1（v1, 2025-01-20）。作者全部任職 Zep AI。預印本，未經同儕審查；且是商業產品的技術報告，讀時要留意這一點。
  • 對應待查問題：⑧本體學習與 schema 歸納、⑥時間記法（兼涉①）
  • 一句話定位：這是二十四篇裡唯一一個把「原始資料層」與「抽出的知識層」用雙向索引綁在一起、讓每筆知識都能回溯到來源的系統，同時也是唯一處理「相對時間怎麼錨定」與「事實何時失效」的系統。這兩件事正是本專案紅線第 3 條與硬約束 3 要的東西。

1. 貢獻

提出一個給語言模型 agent 用的記憶層服務，底層是動態的、有時間意識的知識圖譜引擎 Graphiti。相對於既有的檢索增強生成（RAG）框架多半處理靜態文件，Zep 要處理的是持續累積、彼此矛盾、會過時的對話資料。它宣稱在兩個既有基準（MemGPT 的 Deep Memory Retrieval、LongMemEval）上勝過當時最好的系統。

2. 知識怎麼被萃取（抽取流程）

輸入單位叫 episode（訊息、文字或 JSON 三種型別，這篇聚焦訊息型）。一則訊息包含相對短的文字與產出這段話的行動者，並帶一個參考時間戳 t_ref。

抽取分幾步：

  1. 實體抽取：處理當前訊息時，連同前 n 則訊息一起給（實作用 n = 4，等於兩個完整對話輪次）當作命名實體辨識的脈絡。說話者自動被抽為一個實體。
  2. 反思（reflection）：抽完後跑一輪受 reflexion 啟發的反思，用意是減少幻覺、提高覆蓋。這一步是模型評自己的產出，與紅線第 2 條有張力。
  3. 實體消解：把實體名嵌入 1024 維向量空間，用餘弦相似度在既有節點裡找相似的；同時對既有實體名與摘要做全文檢索，再撈一批候選。把候選節點加上 episode 脈絡交給模型，用專門的實體消解話術判斷。判定重複時，生成一個更新過的名稱與摘要。
  4. 寫入圖：用預先寫好的 Cypher 查詢，而不是讓模型生成資料庫查詢——理由是確保 schema 格式一致、減少幻覺。

事實（邊）的處理類似：抽出後生成嵌入，做去重。去重的搜尋範圍被限制在「同一對實體之間的邊」，這既避免把不同實體對之間的相似邊錯誤合併，也大幅縮小搜尋空間。

3. 知識怎麼被組織（結構與屬性）

三層子圖，這是全篇最該學的結構。

  • Episode 子圖 G_e：節點是原始輸入資料本身（訊息、文字、JSON）。論文明說它是「非破壞性的資料儲存（non-lossy data store），語意實體與關係從這裡抽出」。Episodic edges 把 episode 連到它提到的語意實體。
  • 語意實體子圖 G_s：實體節點（從 episode 抽出並與既有實體消解過）與實體邊（關係）。
  • 社群子圖 G_c：強連通實體的叢集，節點含該叢集的高層摘要。

雙向索引是關鍵：episode 與其衍生的語意邊互相維護索引，可以雙向走訪——「語意產物可以追溯到來源以供引用或直接徵引，而 episode 也能快速取回它相關的實體與事實」。

他們把這個雙層設計類比為心理學上情節記憶（episodic memory，記得個別事件）與語意記憶（semantic memory，記得概念之間的關聯）的區分。

雙時間模型（bi-temporal），這是第二個該學的東西。兩條時間線：

  • T：事件本身的時序
  • T′：資料進入系統的交易時序

每條邊帶四個時間戳：t'_created 與 t'_expired（屬於 T′，記錄這筆事實在系統裡何時建立、何時失效）、t_valid 與 t_invalid（屬於 T，記錄這筆事實在真實世界中何時開始為真、何時不再為真）。

相對時間的處理：因為每則訊息有 t_ref，系統可以正確解析並轉換訊息內容裡的相對或部分日期——論文舉的例子是「下週四」「兩週後」「去年夏天」，以及「我兩週前開始新工作」。

邊失效（edge invalidation）：新邊可能讓既有邊失效。系統用模型比較新邊與語意相關的既有邊，找出矛盾；發現時間上重疊的矛盾時，把受影響那條邊的 t_invalid 設為使其失效的那條邊的 t_valid。依照交易時間線 T′，一律優先採信新資訊。

社群偵測用標籤傳播（label propagation）而非 Leiden，理由是標籤傳播容易做動態擴充——新節點加入時只看鄰居屬於哪些社群，取多數決指派，再更新該社群的摘要，不必整張圖重跑。他們承認這樣會逐漸偏離完整重跑的結果，所以仍需定期整體刷新。

4. 表示法：是不是三元組？

是屬性圖上的三元組，但帶時間有效區間，而且同一個事實可以在不同實體對之間被抽出多次，藉此以超邊（hyper-edge）的形式建模多實體事實。

有出處（episodic edges 加雙向索引）、有時間（四個時間戳）、沒有信心分數。

5. 資料集

Deep Memory Retrieval（來自 MemGPT）與 LongMemEval 兩個既有基準，都是英文對話。這篇沒有自建語料，也沒有中文、沒有歷史文本、沒有真實訪談。

6. 評估

只評記憶檢索的效果（正確率、延遲、可擴充性），不評知識圖譜建構的正確性。沒有任何地方評估「抽出的實體與事實對不對」——這是一個很大的缺口，讀的時候要記住。

檢索流程分三步：搜尋（餘弦語意相似、Okapi BM25 全文、廣度優先三種併用）→ 重排序 → 建構脈絡字串。

7. 發現的問題與限制

論文自承的：動態社群更新會逐漸偏離完整重跑的結果，需要定期刷新；episode 與語意產物之間的雙向連結「本篇實驗沒有直接檢驗，留待未來工作」。

我讀出來的：

  • 這是商業產品的技術報告，不是同儕審查論文。 作者全部來自同一家公司，評估只做對自己有利的檢索任務，抽取正確性完全沒評。所有數字要打折看。
  • 「優先採信新資訊」這條規則是為客服對話設計的（使用者換了工作、改了偏好，舊的就該失效）。它預設了「後說的比先說的真」，這在口述歷史裡完全不成立。
  • 反思步驟是模型評自己，論文沒有量化它到底減少了多少幻覺。
  • 實體消解最後一步交給模型判斷，沒有程式化的約束（對照 Jing 2007 的最小距離門檻與關係約束）。

8. 對 extract_ohistory 的啟示

這篇要求我更正一個先前的判斷。 我在 _卡點對照表.md 寫過「二十篇裡沒有任何一家做到三元組層級的出處」。Zep 做到了：episodic 子圖保留非破壞性的原始資料，雙向索引讓每一條語意邊都能回到它的來源 episode，論文明說這是為了「引用或直接徵引」。所以正確的說法是：出處鏈條有前例，只是罕見，而且那個前例是商業系統不是學術研究；出處與「口語、評價、歷史材料」三者結合仍然沒有前例。

（一）三層結構可以直接對應我們既有的東西。

Zep 我們
Episode 子圖（非破壞性原始資料） data/srt/ 的逐字稿與 output/experiments/trunks/、sentences.json
Episodic edges（雙向索引） 三元組的 char_span、檔名、時間碼
語意實體子圖 output/registry/（尚未存在）與三層網絡
社群子圖 尚未做

我們其實已經有前兩層，只是沒有把它想成一個「非破壞性資料層加雙向索引」的架構。把它明確化的好處是：出處不再是掛在每筆知識上的欄位，而是圖裡真實存在的一條邊，可以雙向走訪——不只「這條關係出自哪裡」，還能問「這一段話產生了哪些知識」。後者對查核很有用，因為它讓「這段話明明講了 X 卻沒抽出來」變成可以檢查的事。

（二）雙時間模型解決相對時間的錨定，這是硬約束 3 直接要的東西。

CLAUDE.md 說相對時間（「退伍之後」）是把事件接成序列的接續資訊，不得丟掉。但只保留「退伍之後」四個字並不夠，還要能把它接到某個點上。Zep 的做法是每則訊息帶 t_ref，相對表述以它為錨。

我們的對應物是訪談日期加時間碼。這給了一個下界錨點（「這段話是在某年某月說的」），但口述歷史講的是幾十年前的事，t_ref 只能錨定「說話的時間」，錨不了「事件的時間」。所以真正可用的是它的四時間戳結構，而不是 t_ref 本身：

  • t_valid / t_invalid：這件事在真實世界何時為真——多數時候我們只能填「未知」或一個區間，這正是 EDTF 規格（loc2019_edtf-spec.md）要處理的。
  • t'_created / t'_expired：這筆知識何時被我們抽出、何時被推翻——這一層我們目前完全沒有，但它其實就是紅線第 4 條（推理可追溯）在資料結構層的實作。

（三）矛盾的處理必須反著做，但機制可以留。

Zep 遇到矛盾就讓舊邊失效，優先採信新資訊。口述歷史不能這樣——兩位口述者對同一件事的不同說法，兩者都是史料。但它的時間區間機制正好可以拿來記錄矛盾而不消滅它：兩條矛盾的邊都保留，各自帶自己的有效區間與出處，衝突本身成為一個可查詢的狀態，而不是要解決的錯誤。這比 Graphusion 的「裁掉一條」好得多，也比單純「都留著」多了結構。

（四）三個可直接抄的程式化約束。

  1. 邊去重只在同一對實體之間搜尋。 這既防止錯誤合併，也大幅縮小搜尋空間。我們做 output/registry/ 時應該照做。
  2. 用預先寫好的查詢寫入資料庫，不讓模型生成查詢。 這與本專案「程式吃乾機械部分，模型一次只做一件事」完全同向，可以當外部佐證。
  3. 抽取時帶前 n 則的脈絡（他們用 4）。我們目前是單句送進去。這與 Papaluca 的發現（脈絡的效益遠大於模型大小）互相印證，值得當一個具名變因來測：單句、前後各一句、前後各兩句，比較抽出量與逐字合規率。

（五）說話者自動成為實體，這一點我們要更小心。

Zep 直接把訊息的行動者當實體。我們的情形複雜得多——speaker 是說話的人、person 是那一卷的主題人物，兩者不一定相同（許石卷 139 句全是別人在講他）。但「講述者本身就是圖上的一個節點」這個想法是對的，而且它正是敘事層網絡（講述者→被講述）已經在做的事。

該避免的

  • 反思步驟（模型評自己的抽取）踩紅線第 2 條，不採用。要提高覆蓋應該用多輪投票這類程式化訊號（gu2024 證實有效）。
  • 實體消解的最後一步不要只交給模型。 Zep 是「檢索候選 → 模型判斷」，中間沒有程式化約束。Jing 2007 的最小距離門檻與關係約束共指應該加在模型判斷之前，把明顯不該合併的先擋掉。
  • 「優先採信新資訊」絕對不能照抄。
  • 它的評估不能引用。 這篇只評檢索效果，完全沒評抽取正確性，而且是廠商自評。

與四條紅線的相容性：紅線 3 相容且是唯一的正面範例（雙向索引的出處鏈條）；紅線 4 部分相容（有交易時間線，但沒有決策紀錄）；紅線 2 衝突（反思步驟、實體消解交給模型判斷）；紅線 1 相容（不用人工標注）。

與 _卡點對照表.md 的對應：第六節（相對時間與時序）、第二節（跨訪談併人的去重約束），以及「前人沒有的四件事」第 1 條需要修正。
