Papaluca 2024_零／少樣本的知識圖譜三元組抽取

來源 extract_ohistory/refs/notes/papaluca2024_zero-few-shot-kg-triplets.md　來源最後修改 2026-09-08　分類 文獻深讀筆記（八節）

  • 完整書目：Papaluca, A., Krefl, D., Rodríguez Méndez, S. J., Lensky, A., & Suominen, H. (2024). Zero- and Few-Shots Knowledge Graph Triplet Extraction with Large Language Models. Proceedings of the 1st Workshop on Knowledge Graphs and Large Language Models (KaLLM 2024), 12–23. ACL Anthology 2024.kallm-1.2。同儕審查（ACL workshop）。澳洲國立大學等。程式碼公開。
  • 對應待查問題：⑧本體學習與 schema 歸納、⑦零標注三元組抽取的參照點
  • 一句話定位：測了六個不同大小的語言模型在零樣本與少樣本下抽三元組的能力，得到一個很難看但很重要的數字——純零樣本的 F1 幾乎是 0。加上從知識庫檢索來的脈絡之後才回到可用水準。結論是：脈絡的品質決定成敗，模型大小只帶來對數級的改善。

1. 貢獻

提出一條用知識庫（KB）動態補脈絡的流程：對每個待處理的句子，從知識庫檢索相關資訊塞進話術，再要模型抽三元組。相對於前人手工寫死的靜態脈絡，他們的脈絡是依句子動態檢索的，因此更靈活、更不綁資料集。另外，他們測了從 1 億到 650 億參數共六個模型，因此能同時分析「模型大小」與「脈絡品質」兩個因素各自的貢獻。

2. 知識怎麼被萃取（抽取流程）

基本話術很簡單：「以下提供一段文字。從中抽出最多 {max_triplets} 個 (主詞, 述詞, 受詞) 形式的知識三元組」，附兩個固定範例。他們試過三種話術變體，F1 沒有顯著差異，所以主實驗只用這個基本版。

知識庫補脈絡分兩種形式：

  • 脈絡三元組（他們稱 0.5-Shots）：從知識庫檢索若干條與輸入句相似的三元組附在話術裡。這些三元組提示模型「該預期哪些關係與實體」，但不示範句子長什麼樣。
  • 句子—三元組配對（Few-Shots）：檢索若干組「例句加該例句應抽出的三元組」，取代話術裡那兩個固定範例。

檢索方式：把知識庫裡每條三元組的 (主詞, 述詞, 受詞) 字串用小型句子編碼器 MiniLM 編成向量存進索引；推論時把輸入句也編碼，用餘弦相似度取最相似的前 N 條。還多做一步：從這 N 條裡，每種關係型別只取前兩條，以免脈絡被單一高頻關係佔滿——他們指出不這樣做會得到偏向某一關係的分布，對含多種關係的句子不利。

知識庫是從該資料集的訓練集與驗證集建的。

3. 知識怎麼被組織（結構與屬性）

純三元組，述詞必須對應到知識庫封閉關係集裡的某一種。無出處、無時間、無信心分數。這篇的重點不在表示法，在抽取條件。

4. 表示法：是不是三元組？

是，而且是受封閉關係集約束的三元組——主詞受詞要對應知識庫的節點，述詞要對應知識庫允許的邊型別。這一點在解讀它的數字時很關鍵，見第 8 節。

5. 資料集

兩個標準基準，都是英文：

  • WebNLG（Zheng 等人 2017 修訂版）：5,019 訓練／500 驗證／703 測試句，171 種關係，每句平均 2.29 條三元組。句子結構較線性、簡單。
  • NYT（Riedel 等人 2010）：56,195／5,000／5,000 句，24 種關係，每句平均 1.72 條。這個資料集本身就是用遠距監督建的（把 180 萬篇紐約時報文章對齊 Freebase）。

模型：GPT-2（1 億／15 億）、Falcon（70 億／400 億）、LLaMA（130 億／650 億），全部用 8-bit 量化在本地跑，溫度 0.1。他們也試了 instructed／chat 微調版本，結果總是持平或更差，所以主報告用 base 版。

6. 評估

微平均 F1，對照的是既有的完全微調模型（表 3）：NovelTagging 0.283／0.420（WebNLG／NYT）、CopyRE 0.371／0.587、GraphRel 0.429／0.619、OrderCopyRE 0.616／0.721、UniRel 0.947／0.937。

零樣本與 2-shots，不給知識庫脈絡（表 4）：

模型 WebNLG 0-Shot WebNLG 2-Shots NYT 0-Shot NYT 2-Shots
GPT-2 base 0.000 0.006 0.000 0.000
GPT-2 xl 0.000 0.037 0.000 0.000
Falcon 7b 0.000 0.066 0.000 0.002
Falcon 40b 0.021 0.158 0.000 0.007
LLaMA 13b 0.006 0.129 0.000 0.002
LLaMA 65b 0.041 0.219 0.000 0.017

加上知識庫脈絡（表 5）：

模型 WebNLG 0.5-Shot WebNLG 5-Shots NYT 0.5-Shot NYT 5-Shots
GPT-2 base 0.249 0.430 0.175 0.375
GPT-2 xl 0.297 0.517 0.193 0.448
Falcon 7b 0.381 0.567 0.250 0.519
Falcon 40b 0.345 0.615 0.226 0.547
LLaMA 13b 0.374 0.609 0.247 0.582
LLaMA 65b 0.377 0.677 0.243 0.647

三個讀法：

  1. 零樣本近乎全滅。 NYT 上六個模型全是 0.000。
  2. 脈絡的效益遠大於模型大小。 GPT-2 base（1 億參數）加上脈絡三元組，F1 0.249，勝過 LLaMA 65b（650 倍大）不加脈絡的 0.041。作者的說法是模型大小只帶來對數級改善。
  3. 句子—三元組配對的範例比單純的脈絡三元組更有效（0.5-Shot 對 5-Shots 差距很大），因為前者不只告訴模型有哪些關係，還示範了「這種句子該抽成什麼」。

他們另外量了檢索脈絡的品質（圖 3）：正確三元組出現在檢索回來的脈絡裡的機率，隨檢索數量 N 上升。這個機率與最終抽取效能強烈相關——NYT 表現差的原因之一就是檢索器在 NYT 上撈不到相關脈絡。

無 LLM 自評、無 LLM 評審。

7. 發現的問題與限制

論文自承的：NYT 難的原因有二——句子結構複雜（從屬子句多、關係常隱含）；而且NYT 的標準答案往往只涵蓋句中實際關係的一個子集，所以沒有訓練範例時，模型無從得知哪些關係該抽、哪些不該。

我讀出來的：

  • 「零樣本 F1 = 0」的意思比字面窄。 這是在「述詞必須對應封閉關係集」的評分下算的。模型不是抽不出任何東西，是抽出的東西對不上那個封閉集。換一種評分（例如不要求對應封閉集，只看抽出的內容是否忠於原文），數字會完全不同。論文沒有做這個對照，這是它最大的盲點。
  • 知識庫是從訓練集與驗證集建的，所以「零樣本」這個詞用得很鬆——模型沒有被微調，但脈絡來自標注資料。嚴格說這是檢索增強的少樣本，不是零樣本。
  • instructed 版本更差，這件事沒有被解釋。 只有一句話帶過。對想用本機 instruct 模型的人來說，這是需要自己驗證的重要訊號。

8. 對 extract_ohistory 的啟示

這篇最該記的是一個必須小心引用的數字，以及一條清楚的行動指引。

（一）「零樣本三元組抽取幾乎是 0」不能直接套到我們身上，但要知道它為什麼。

他們的評分要求述詞對應到知識庫的封閉關係集。我們的兩條線性質不同：

  • triples/ 用 life_nodes.py 的動詞表界定述詞，有封閉集，所以比較接近他們的設定；差別在我們的動詞表是從語料的實際用詞來的，不是外部資料庫的抽象關係名。
  • triples_free/ 不限動詞、模型自判，沒有封閉集，所以他們的數字對這條線幾乎不適用。

這個區別要寫進報告。否則引用「零樣本 F1 近乎 0」會誤導——那是「零樣本且要對上外部 schema」的成績，不是「零樣本抽取」本身的成績。

（二）NYT 的困難就是我們的困難，而且他們講出了原因。

「標準答案只涵蓋句中實際關係的一個子集，所以模型無從得知哪些該抽、哪些不該」——這正是 triples_free/ 讓模型自己判斷「什麼算知識」時碰到的問題。差別在他們有標準答案可以怪，我們沒有。這意味著：在沒有標準答案的情況下，「該抽什麼」這個問題只能靠判準說清楚，不能指望模型自己想出來。這替 criteria.md 這類判準文件的必要性提供了論證。

（三）行動指引：與其換更大的模型，不如給更好的脈絡。

GPT-2 base 加脈絡勝過 LLaMA 65b 不加脈絡。這與 NER4all 的發現同向（脈絡帶來 +11% 召回，話術技巧只有 1–2%），兩篇互相印證。對我們的具體意涵：目前所有實驗都是把單一句子丟給模型，沒有給任何脈絡。 可以做的是——

  • 把該句前後幾句一併給（Zep 用前 4 則訊息，Jing 2007 也強調輪次脈絡）；
  • 把該卷已經抽出的人物清單當脈絡（這不違反紅線 5，因為那是我們自己抽的，不是人工名冊）；
  • 把同一位被講述者在別卷已抽出的三元組當脈絡（這正是他們的「脈絡三元組」，而且直接服務跨訪談併人）。

第三種最接近他們的做法，也最值得試，因為它同時是抽取增強與跨卷連結。

（四）檢索脈絡時要控制關係分布。

他們每種關係型別只取前兩條，以免脈絡被高頻關係佔滿。我們的語料裡「唱」「寫」「錄」是高頻述詞，若不控制，檢索回來的脈絡會全是這三種，反而壓抑罕見但有價值的關係（引薦、拜師、頂替）。這是一行程式的事，但不做會系統性偏斜。

（五）本機 instruct 模型可能不如 base 模型。

他們的 instructed／chat 版本「總是持平或更差」。我們用的是 LM Studio 上的 gemma 與 hermes，都是 instruct 系列。這是一個可以低成本驗證的變因：同一個模型的 base 與 instruct 版本各跑一遍陳志遠卷，比較逐字合規率與抽出量。但要注意 base 模型不遵守格式，我們的程式端得更寬容——這與 judgment-and-words-must-coincide 那條經驗一致（模型不照格式時先在程式端寬容，別往話術加規則）。

該避免的

  • 不要用他們建知識庫的方式。 他們的知識庫來自訓練集與驗證集的標注資料。我們若拿 entity_stage1_final.csv 做同樣的事就違反紅線 5。可以當脈絡來源的只有：我們自己抽出來的東西、或完全外部的庫。
  • 不要把 0.677 當成天花板。 那是英文、封閉關係集、有標注知識庫可檢索三個條件下的成績。

與四條紅線的相容性：紅線 2 完全相容（無模型自評、無 LLM 評審）；紅線 1 有張力（知識庫來自標注資料，但那是資料集自帶的，不是他們另外標的）；紅線 3 不相容（無出處）；紅線 5 需注意（見上）。

與 _卡點對照表.md 的對應：第一節（動詞表／封閉集）、第三節（脈絡的效益）。
