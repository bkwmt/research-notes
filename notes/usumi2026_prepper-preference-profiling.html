usumi2026_PrePPER 偏好模式人物側寫

來源 extract_ohistory/refs/notes/usumi2026_prepper-preference-profiling.md　來源最後修改 2026-09-09　分類 文獻深讀筆記（八節）

  • 完整書目：Usumi, Taisuke, Akiko Masaki, Sanae Muramatsu, Akira Sakamoto, and Takeharu Eda. 2026. PrePPER: A Preference Pattern-based Profiling Framework for Explainable Recommendation. Proceedings of the Fifteenth Language Resources and Evaluation Conference (LREC 2026), pp. 705–715. ELRA. ACL Anthology 編號 2026.lrec2026-1.52（文中未列 DOI）。同儕審查：已通過（LREC 主會議論文；作者為 NTT 軟體創新中心的產業研究團隊）。
  • 對應待查問題：⑥來歷標記／極性／時間記法（正負極性分開處理、「重要性」怎麼記）；⑧本體學習與 schema 歸納（「偏好模式」不是預先定義、是從資料聚出來的）；⑤無 gold standard 評估（用 LLM 當評審＋極小規模人工評分，是反面教材）。①LLM 抽取只沾到邊（抽取步驟整段借用 EXP3RT）。
  • 一句話定位：推薦系統論文。從使用者寫的商品評論抽出「喜歡／不喜歡」的句子，用向量聚類把它們歸成幾種「偏好模式」，再以自然語言寫成使用者側寫（user profile）與商品側寫（item profile），並把每種偏好的「重要性」寫進側寫裡，目的是提高評分預測的準確度。與本專案相關的不是推薦，而是它處理的正是「一個人對人事物的品味怎麼被結構化地寫下來」，也就是本專案 goût 敘述那一層的問題；它同時示範了一種把「重要性」寫進自然語言的做法，以及一套用 LLM 評 LLM 的評估，兩者都值得拿來對照本專案的紅線。

1. 貢獻

論文自稱三項貢獻：

  1. 一種以偏好模式為骨架的側寫結構。先前的自然語言側寫（UPR、EXP3RT）把偏好句平鋪成一段話，使用者側寫與商品側寫各談各的面向（例如一邊寫「角色刻畫」、另一邊寫「閱讀體驗」），兩邊對不上。PrePPER 讓兩種側寫都按同一組偏好模式分節，逐節對照。
  2. 一種判定偏好重要性的方法：某使用者在某個偏好模式下的句子越多，就把該模式視為對他越重要，並把這件事寫進側寫。
  3. 側寫可以直接替換進既有推薦系統（UPR、EXP3RT 兩種架構），不必改模型，實驗顯示替換後評分預測誤差下降；用 8B 的開源模型建側寫，也能勝過原本靠 GPT-3.5 蒸餾的 EXP3RT。

它在推薦領域解決的問題很具體：側寫裡「哪個偏好比較重要」沒被寫出來，以及使用者側寫與商品側寫的面向不一致。這兩點放到本專案，前者對應「一個人被講述的諸多面向裡哪些是主要的」，後者對應「跨訪談合併時不同口述者談同一個人的面向不一致」，第 8 節細談。

2. 知識怎麼被萃取（抽取流程）

輸入是使用者評論（英文，來自電影資料集 IMDB 與圖書資料集 Amazon-Book），每則評論附評分與商品資料。流程四步，全是單次呼叫、沒有多 agent 分工：

  1. 偏好抽取：讓 LLM 把每則評論改寫成「喜歡：……／不喜歡：……」的短句。這一步完全沿用 EXP3RT（Kim et al. 2025）的做法，論文沒有給自己的提示詞，也沒有評估這一步抽得準不準。
  2. 偏好聚類：把全體使用者的「喜歡」句與「不喜歡」句分開，各自用文字嵌入模型（text-embedding-3-small 或 Sentence-BERT）轉成向量，再用 K-means++ 各分成 K=3 群。分開的理由是正負混在一起會讓群數膨脹、群的邊界模糊。然後按使用者 ID 與商品 ID 把各群裡屬於某人、某商品的句子撈出來，數每群有幾句。
  3. 偏好模式抽取：對每一群，只取離群中心最近的 200 句（Llama3 用 150 句），三群一起送給 LLM，要它替每群取一個簡短標籤（例如「引人入勝的敘事」），並明令「除非真的相同，不要給不同群同一個標籤」。
  4. 側寫建構：對每個使用者、每個商品，按偏好模式逐節請 LLM 把該節的句子摘成最多兩點。重要性怎麼進去？句數多的模式，提示詞裡塞一句「用更強烈、更斬釘截鐵的形容詞」；句數少的塞「用較柔和、較溫和的形容詞」。也就是說，重要性不是寫成數字或欄位，而是變成形容詞的語氣強弱。

用的模型是 GPT-4o-mini 與 LLaMA3-8B-Instruct，兩組各自配一個嵌入模型，以區分閉源與開源版本的結果。

3. 知識怎麼被組織（結構與屬性）

沒有本體（ontology），也沒有預先定義的類型表。「偏好模式」這個類型學是資料驅動、事後歸納的：先聚類再貼標籤，每個資料集各得正向三類、負向三類，而且類別內容隨資料集、隨 K 值、隨嵌入模型變動，論文沒有報這些類別在不同設定下穩不穩定。所以它的類型學回答不了「偏好有哪幾種」這種問題，只回答「這批評論裡最常見的三種講法是什麼」。

側寫的結構是：極性（喜歡／不喜歡）→ 偏好模式（三類）→ 兩點以內的自然語言摘要。使用者側寫與商品側寫共用同一組模式，這是它「對齊」的全部機制。

跨文件的合併方式很單純：同一個使用者的所有評論、同一個商品收到的所有評論，按 ID 撈在一起再摘要。沒有去重、沒有衝突處理（同一個人先前說喜歡、後來說不喜歡，會被分別歸進正向與負向兩邊各自摘要，兩邊互不知道彼此），也沒有時間順序。

4. 表示法：是不是三元組？

不是三元組。表示法是帶極性與類別分節的自然語言條列（bullet list），每節最多兩點。

  • 出處欄位：沒有。摘要出來的每一點無法回指是哪一則評論、哪一句話；第一步的「喜歡／不喜歡」短句本身就已經是改寫，不是原文跨距。
  • 時間資訊：沒有。資料集按時間切訓練／驗證／測試，但側寫裡不記任何時間。
  • 信心分數：沒有明確的數值。「重要性」由句數決定，但最後只以形容詞語氣寫進文字，原本的句數不留在產出裡。這等於把一個可以量化、可以驗證的訊號，轉成一個既讀不回來、也無法程式化檢查的修辭效果。

它選自然語言而非三元組的理由是推薦領域的「可解釋、可審視」（scrutability）：使用者可以自己讀、自己改側寫，改完推薦跟著變，不必重新訓練模型。這個理由在本專案有對應物（人物頁要給人讀），但本專案的可審視性靠的是出處，不是靠文字好讀。

5. 資料集

兩個公開的英文推薦資料集，都是商品評論，沒有中文、沒有歷史文本、沒有口語或訪談：

  • IMDB（來自 PEARL 資料集，Kim et al. 2024）：電影，評分 1–10。清理後 859 位使用者、1,155 部電影、19,124 筆互動。
  • Amazon-Book（Hou et al. 2024a）：圖書，評分 1–5。清理後 10,761 位使用者、10,084 本書、118,705 筆互動。

清理規則把互動少於五次的使用者與商品全部剔除。按時間戳以 8:1:1 切訓練／驗證／測試。沒有提出新資料集。

6. 評估

三層評估，層層都有可議之處：

  1. 主指標是外部任務：評分預測的 MAE 與 RMSE，也就是「用了新側寫之後推薦準不準」。這不直接衡量側寫寫得對不對，只衡量對下游任務有沒有用。基準模型 MF、P5、LLMRec 的數字直接引用 EXP3RT 論文，沒有重跑。另分暖啟動／冷啟動兩組子集報數。
  2. LLM 當評審（LLM-as-a-judge）：每個資料集抽 200 筆（高分低分各半），由 GPT-4.1 按四項標準打 1–5 分：可讀性、資訊量、多樣性、關聯性（使用者側寫與商品側寫的面向是否對得上）。結果 PrePPER 在多數項目接近滿分（5.00）。注意兩件事：側寫是 GPT-4o-mini 寫的、評審是 GPT-4.1，同一家族的模型評自家產出；「關聯性」這一項量的正是方法本身被設計來最大化的東西，等於用結果驗證設計目標，難以視為獨立證據。
  3. 人工評分：每個資料集只有 20 筆、三位評審，同樣四項 1–5 分，另用 Borda 計數消除給分極端者的影響。沒有報評審間一致性，沒有說評審是誰、是否為作者以外的人。20 筆的規模只能算示意，不能算證據。

沒有 gold standard，也沒有對第一步抽取（評論→喜歡／不喜歡短句）或第三步標籤（群→偏好模式名稱）做任何正確性檢查。整篇的「側寫品質」證據，就是 LLM 評分與 20 筆人評。

7. 發現的問題與限制

論文自承的限制只有兩條：側寫品質依賴評論品質；沒寫評論的使用者無法建側寫。

我讀出來、它沒明講的：

  • 「提得多＝重要」是假設，不是發現。 3.4.1 節明說這是 hypothesize，但全文沒有任何實驗檢驗它，連消融（拿掉重要性語氣、只留分節）都沒做，所以「重要性」這一貢獻的效果無從分離。在評論語料裡這個假設或許還說得通，換到口述歷史就站不住（見第 8 節）。
  • 重要性的門檻沒交代。 幾句算「高度重要」、幾句算「較不重要」，論文沒有給數字，也沒說是絕對句數還是相對比例。
  • K=3 的選法有疑慮。 表 3 顯示 Amazon-Book 在 K=2 最好，論文仍統一用 K=3；而且表 3 的比較看起來是在測試集上做的，這等於用測試集調超參數。
  • 側寫是否吃到測試集的評論，沒有說明。 商品側寫是把「所有使用者」對該商品的評論聚合起來寫的；如果其中包含測試集那筆互動的評論，評分預測就有洩漏。論文對此一字未提。
  • 抽取端零檢驗。 第一步整段借用 EXP3RT，換了模型（GPT-4o-mini／Llama3 取代 GPT-3.5 蒸餾）卻沒有重新驗證抽出來的短句是否忠於原評論。
  • 剔除稀疏使用者是推薦領域的慣例，卻把「只留下有足夠資料的人」這個選擇性偏誤帶進了所有結論。
  • 正負分開聚類之後，同一個人對同一件事前後矛盾的評價會被切成兩邊、各自摘要，衝突被結構本身消音了。

8. 對 extract_ohistory 的啟示

先回應指派時點名的四個問題。

（一）「偏好模式」的類型學是什麼？有沒有把重要性分級？ 類型學是聚類歸納出來的、每個資料集三正三負、事後由 LLM 命名，不是預先設計的類別表，也不做穩定性檢查。重要性有分級，但只有粗略兩檔（多／少），且判準是句數，最後以形容詞語氣寫進文字，數字不留。對本專案而言，這種「用資料聚出類別」的路線正是 ORC（把關係表述聚成同一類）那一條，但本專案已經有 life_nodes.py 六類動詞反推的人事時地物型別，不需要再靠 K-means 猜類別；真正可借的是它「正負分開、再分節」的兩層結構：goût 敘述若要建人物頁，先按極性分、再按對象型別（人／作品／器材／組織……）分節，比平鋪一段話清楚得多。重要性那部分則該反著學：句數可以留，語氣不能用來編碼句數（下詳）。

（二）自然語言側寫的可解釋性設計，對「以人物為單位、跨訪談合併」的人物頁有沒有參考？ 有一個結構上的對應很值得注意：PrePPER 的商品側寫是把「所有使用者對這個商品說了什麼」聚合起來寫成一頁，這在形式上就是本專案要做的「他述」聚合——把多位口述者對同一個未受訪者的證詞併成一條生命過程；而它的使用者側寫對應「這位講述者自己的品味」。兩種側寫共用同一組分節、逐節對照，這個對照面板的想法可以借：一個人物頁若同時放「他自己怎麼說（自述）」與「別人怎麼說他（他述）」，按同一組型別分節對照，讀者一眼就能看出哪些面向只有別人在講、哪些面向兩邊說法不合。CLAUDE.md 定調「他述是主要材料」，這種對照版面正好把他述放到與自述同等的位置。

但可借的只到「版面」為止。PrePPER 的側寫每一點都沒有出處，兩點以內的壓縮把原句全部丟掉，這與紅線 3 直接衝突。本專案若做人物頁，每一點後面必須掛（檔名、時間碼、口述者），而且應該是原文跨距而不是模型改寫；ORSE 這條線「模型只圈字、程式驗證逐字出現」的做法已經比它嚴格得多，不能為了版面好看退回去。

（三）評估是否用 LLM 當評審？ 是，而且是主要的品質證據：GPT-4.1 評 GPT-4o-mini 的產出，200 筆四項打分，加上 20 筆人評。這不是紅線 2 說的「叫模型自評信心」，但是同一個精神的近親：用模型的主觀評分代替可檢驗的訊號。本專案該避免。它四項標準裡有三項（可讀性、資訊量、多樣性）在本專案都能換成程式化訊號：可讀性不重要，資訊量可以數「有出處的獨立事實數」，多樣性可以數「涵蓋幾種型別、幾位口述者佐證」；第四項「關聯性」（自述與他述面向是否對得上）則正是 told_vs_credits 那類程式化比對在做的事。也要記住它的小規模人評沒報一致性，本專案若做人工抽查，一致性要報。

（四）哪些部分純屬商業推薦、對本專案無用？ 評分預測的 MAE／RMSE、MF／P5／LLMRec 基準、QLoRA 微調參數、暖啟動／冷啟動分析、「側寫替換進推薦架構」的整套實驗設計，全部與本專案無關。「剔除互動少於五次的使用者」這個前處理更是本專案不能學的：未受訪者常常只被提到一兩次，那一兩句正是要保住的材料。

與 goût 框架的關係（該避免的地方）。 PrePPER 把品味當成一個人的穩定屬性，可以從評論裡加總、以頻率排序。Hennion 的 amateur／goût 觀點恰恰相反：品味是一種活動、在特定場合裡被做出來，隨情境與對象變動。口述歷史更放大這個差距：訪談裡某個話題被提到的次數，主要反映訪談者問了什麼、口述者當時想講什麼，不反映那件事對他「有多重要」。所以「提得多＝重要」這個假設不能搬進本專案；被講述的次數可以當一個維度報（corpus_bias.py 的「被講述集中度」已經在做），但不能拿它替代重要性判斷，更不能把它轉成語氣寫進人物頁。

最重要的一個啟示：自述與他述按同一組型別分節、逐節對照的人物頁版面，能把「他述是主要材料」這個立場直接做成可讀的介面，並讓兩邊面向不合之處自己浮出來。

最該避免的一個地方：把可量化的訊號（句數、佐證人數）轉成形容詞語氣寫進自然語言。這一步不可逆、不可驗證，違背紅線 2 與紅線 4 的精神；訊號要以欄位保留，人物頁的文字只負責呈現、不負責編碼。

與四條紅線的對照：紅線 1（不做配對式 gold standard）——它沒有 gold standard，這點相容，但它用 LLM 評審填補空缺，本專案改用程式化訊號；紅線 2（不叫 LLM 自評）——它沒叫模型自評信心，但 LLM-as-a-judge 是近親，不採；紅線 3（強制出處）——衝突，側寫完全沒有出處；紅線 4（可追溯）——衝突，兩點壓縮與語氣編碼都是不可逆的資訊損失。
