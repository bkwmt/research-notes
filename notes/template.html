深讀筆記：模板與撰寫說明（給閱讀 agent）

來源 extract_ohistory/refs/notes/_筆記模板與說明.md　來源最後修改 2026-07-22　分類 索引與回顧

這份檔案是 refs/ 底下每一篇文獻深讀筆記的統一規格。你（閱讀 agent）會被指派一篇 PDF， 讀完後在 refs/notes/<原檔名>.md 寫出一份筆記，嚴格照下面的八節結構。

這個專案在做什麼（寫「啟示」那節時要對得上）

extract_ohistory：把 102 位資深音樂人、314 個口述歷史逐字稿（SRT），抽成結構化知識 （實體、事件、關係，外加受訪者對人事物的品味／評價敘述，內部稱 goût 敘述）， 每一筆都附時間碼出處，最後接成一個有向的口述歷史網絡，銜接社會網絡分析與一篇已完成的博論。

關鍵：這個專案的知識表示不是純三元組（subject-predicate-object）。它用的是 實體／事件／關係／goût 敘述的混合結構，而且每筆強制附出處。所以「這篇論文用什麼表示法、 是不是三元組、有沒有出處與時間欄位」對本專案特別重要。

四條方法論紅線（你在第 8 節評估「可借用／該避免」時要對照）： 1. 不對抽取／消歧結果做人工標註配對式的 gold standard（實體層有一份人工名冊當對照，事件與關係層沒有）。 2. 絕不叫 LLM 自評信心分數；信心由程式化訊號推導（出處有效性、格式合規、穩定性、數值合理性、跨人佐證）。 3. 每筆知識強制附出處（檔名、時間碼、口述者、段落）。 4. 推理過程可追溯，中間產物全部落檔。

撰寫語言與風格（硬性要求）

  • 全篇繁體中文（臺灣用語）。禁止簡體、禁止中國大陸詞彙（用「影片」不用「視頻」、「資訊」不用「信息」、「記憶體」不用「內存」）。
  • 讀者是人文學者，不是工程師。描述工程流程時，先用白話講清楚「這一步在做什麼、為什麼」，再補上必要的術語與一句話定義。專有名詞第一次出現用括號附原文。
  • 不要逐頁復述。抓論文真正的主張、方法與證據。
  • 語氣要有判斷力：不只轉述論文自己怎麼說，也要讀出它沒說清楚或可疑的地方。

閱讀深度

  • 綜述／survey／roadmap／方法指南（篇幅通常很長）：抓框架、分類法、關鍵結論與它整理出的問題清單，不要陷進每一篇被它引用的細節。
  • 單一系統或方法的論文（篇幅較短）：把流程、schema、實驗設定與數字讀細。

八節模板（照抄這個結構，標題保留）

# <作者年份_短標題>

- **完整書目**：作者. 年. 標題. 場域（期刊／會議）. DOI 或 arXiv 編號. 同儕審查狀態.
- **對應待查問題**：①LLM 抽取／KG 建構現況 ②agentic 建構 ③harness／agent 評估 ④口述歷史／數位人文 ⑤無 gold standard 評估（可多個）
- **一句話定位**：這篇在做什麼、為什麼跟本專案有關。

## 1. 貢獻
這篇宣稱的主要貢獻是什麼？在它的領域裡解決了什麼別人沒解決的問題？

## 2. 知識怎麼被萃取（抽取流程）
輸入是什麼？分幾步？單次抽取還是多步／多 agent 分工？如果是多 agent，各自負責什麼、怎麼交棒？
用白話把流程講清楚。

## 3. 知識怎麼被組織（結構與屬性）
抽出來的東西怎麼安排成結構？有沒有 schema 或本體（ontology）？實體、關係、屬性欄位怎麼定義？
有沒有跨文件的去重、實體合併、衝突解決？如果有「重新安排既有結構」的步驟（例如融合、精煉），說明它怎麼做。

## 4. 表示法：是不是三元組？
這篇的知識用什麼形式表示？（純三元組 / n-ary 關係 / 事件框架 / 屬性圖 property graph /
文字摘要節點（如社群摘要）/ 受本體約束的三元組 / 其他）
有沒有出處欄位（provenance）、時間資訊、信心分數？如果不是三元組，它為什麼選別的表示法？

## 5. 資料集
用什麼語料做實驗或評估？語言（有沒有中文）、規模、領域（有沒有歷史文本、口語、訪談）？
資料是公開的還是自建的？有沒有提出新的 benchmark／資料集？

## 6. 評估
怎麼判斷做得好不好？有沒有 gold standard（人工標準答案）？用什麼指標（P/R/F1、其他）？
有沒有用 LLM 自評或 LLM 當評審（LLM-as-a-judge）？人工介入到什麼程度？
評估設計本身有沒有問題（例如用 LLM 驗證 LLM 的循環）？

## 7. 發現的問題與限制
論文自己承認的限制；以及你讀出來、它沒明講的疑點或弱點。

## 8. 對 extract_ohistory 的啟示
哪些做法可以借用？哪些該避免？跟上面四條方法論紅線是相容還是衝突？
