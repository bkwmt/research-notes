1. 怎麼讀

判斷只有四個值：

  • 可借：想法可以重寫進本專案的程式（對方零 LICENSE，一律重寫不取用）。
  • 先例：設計方向相同，寫作時可引為同行做法。
  • 對照：寫作時當差異點，用對方的公開紀錄逐條證明。
  • 無關：對本專案沒有影響。

差異類型回答「差在哪一段」，只有五個值：

差異類型 問的是 怎麼看出來
提示詞 模型被問什麼、答案是什麼形狀（自由寫、選編號、圈原文） 本研究貼程式裡的話術原文；對方提示詞未公開，從輸出欄位反推，標「推定」
管線設計 哪一步由誰做（模型、程式、人）、順序、有沒有迴圈 第 3 節的流程圖
邏輯判斷 程式規則的判準，逐筆可覆核的那種 本研究貼程式原文或虛擬碼；對方只有欄位的值域與投影片的一句話
資料與表徵 輸入資料與產出物的形狀：出處粒度、單位、本體 JSON 欄位、TTL、海報格
釋出 授權、可重現、中間產物 儲存庫檔案樹、release

證據寫到頁碼、檔名或鍵名。對方的投影片頁碼指 NKOS 2026 PDF；本研究的「第 n 格」指海報文案正本的格號，程式檔指 local_llm/experiments/。對方的抽取程式封在 NarraGraph 二進位檔裡，凡是「程式裡怎麼做」的問題只能答「未載明」；本頁所有標「推定」的句子都是從輸出欄位反推，不是看到程式。

3. 兩條管線並排

每一列是一個可比較的階段。方框顏色是「這一步由誰做」：模型紅、程式藍、人灰虛線；對方那邊凡是從輸出反推的標「推定」。左側紅色虛線是對方的綱要修訂迴圈（投影片第 21 頁「extraction as evaluation of the schema」）。圖由 sources/fig_pipelines.py 產生，內容改那支程式。

讀圖的三個重點：

  1. 模型碰到資料的次數。 對方四次（實體、共指、關係、驗證的 consolidator），每一次都在寫字；本研究三次（句界、共指、關係），每一次都在選。
  2. 人站的位置。 對方在輸出端（工作台回讀、修綱要），本研究在輸入端（設計選項與話術）。兩邊都是人在迴圈，位置相反。
  3. 程式做的事不同。 對方的程式在前後兩端（切句、分群、網絡分析）；本研究的程式夾在每一次模型呼叫的前後（枚舉候選、逐字驗證、查表、定年）。

4. 逐面向：差異落在哪一段

每個面向：差異類型、對方、本研究、判斷（括號裡是證據），有程式可貼的就貼程式。

4.1 起點

  • MeDoraH：逐字稿切成「前一對＋當前對」的話輪對送模型，實體、型別、關係由模型一次產生（schema-free 第一趟）。
  • 本研究：管線從人工名冊出發，程式先把 5,335 筆實體定位到句子，模型只在已定位的兩端之間找關係。

4.2 模型的角色

差異類型：提示詞。

  • MeDoraH：生成式。一筆輸出要模型填十幾個欄位，含 canonical_name、本體類別、關係的 surface_form 與 property、知態四欄、理由。
  • 本研究：選擇題。一行四欄，三欄受限（組號、原文連續字、該組裡的一個名字），第四欄自由但不參與任何程式決定。
  • 判斷：對照，這是本研究的方法主張（證據：Test_OntologyPopulation.json 欄位；orse_exp.py 第 2 區；海報第 3 格標題與原則框）。

4.3 用字與出處

差異類型：邏輯判斷（兼資料與表徵）。

  • MeDoraH：證據句保留在 evidence_text，句 id 在 evidence_sources；304 筆與 655 筆都 100% 帶句 id。但證據句是模型抄的，有沒有程式比對過原文未載明；合併檔退回話輪層；原始逐字稿無時間碼。
  • 本研究：模型的答案對齊回原文，取它涵蓋的原文區間當跨距；跨距永遠是原文的字，字元座標對回 SRT 時間碼。逐字命中與模糊對齊分開統計，不混算。
  • 判斷：對照（證據：Combined_Interviews.json 無 evidence_sources；03 §5.5.2；_verbatim.py、orse_exp.py 的 FUZZY 三個參數；海報第 3 格原則「The words stay the transcript's」）。
# 本研究（_verbatim.py 的規則＋ orse_exp.py 的參數；虛擬碼）
def take_span(answer, text):
    a       = norm_verbatim(answer)         # NFKC、刪句讀、留成對符號「」〈〉《》
    t, idx  = norm_with_map(text)           # 同樣正規化，另留「正規化後第 i 字來自原文第幾字」
    hit = exact_locate(a, t)                # 逐字命中
    if hit is None and FUZZY_ALIGN:
        hit = fuzzy_align(a, t, min_ratio=0.6, max_stretch=2.5)   # 落檔標「模糊對齊」，分開統計
    if hit is None or not (1 <= len(hit) <= 30):
        return None                         # 落空：記錄，不補救
    start, end = idx[hit.start], idx[hit.end - 1] + 1
    return text[start:end], (start, end), timecode_at(start)      # 用原文的字；座標 → 時間碼

4.4 共指

差異類型：提示詞＋邏輯判斷。

  • MeDoraH：655 筆的主詞沒有任何代名詞，可知模型在抽取時已把「I」改寫成 Judy Malloy（推定）。改寫發生在哪一趟、用什麼規則，未載明。

4.5 他述

差異類型：邏輯判斷。

  • MeDoraH：合併檔 42.8% 的 PERSON 主詞不是講述者，但沒有欄位標記、不是分析對象；attribution_type 由模型填（general_attribution 140、direct_quote 55、indirect_report 11、空值 98）；前處理排除引述與轉述。
  • 本研究：他述是主要材料。來歷由程式判定，判準只有一條。
  • 判斷：對照，與硬約束 1 正面衝突（證據：03 §5.5.2；vlachidis §8(5)；海報第 4 格；build_network.py）。
# 本研究（build_network.py 原文）
def provenance(speaker, a: str, b: str) -> str:
    """來歷（epistemic status）：這段話的說話者是不是關係的當事人。
    由程式判定，不問模型（紅線第 2 條）。判準只有一條，可逐筆覆核：
    講述者逐字等於兩端之一 → 自述；否則 → 他述。講述者不明時標「不確定」，不猜。"""
    if not speaker:
        return "不確定"
    if speaker == a or speaker == b:
        return "自述"
    return "他述"

對方的 attribution_type 詞表可以借（direct_quote、indirect_report、general_attribution 分得開），做法不借：那四欄是模型填的，本研究的來歷是程式掃的。

4.6 分類與綱要

差異類型：管線設計。

  • MeDoraH：模型自由命名（單卷 160 型別、436 關係標籤）→ 人收斂成 22 類 → 述詞以 SpanBERT 嵌入、UMAP 降維、HDBSCAN 分群、WordNet 上位詞命名 → 修綱要 → 回到第二趟重抽（hermeneutic loop）。
  • 本研究：程式查六類動詞表，模型第四欄的命名留存但不參與決定；綱要固定；另有事後歸納的動詞詞根與手寫表比一致性。
  • 判斷：對照；另有一處先例：11 種關係模式「粗層保召回、細層靠動詞表」的兩層結構（證據：投影片第 13、14、16 頁；Clustering/*.py 的參數；TTL 的 11 種模式；life_nodes.py、orse_label_exp.py）。
# MeDoraH（投影片第 13、14、16 頁；Clustering 腳本的實際參數）
types    = free_names(pass1_output)                       # 160 型別、436 標籤
classes  = human_collapse(types)                          # 22 類：7 頂層＋15 子類
emb      = SpanBERT(predicates)                           # checkpoint 未載明；產生嵌入的套件不在儲存庫
low      = UMAP(emb, n_neighbors=100, n_components=50, min_dist=0.1, metric="cosine")
clusters = HDBSCAN(low, min_cluster_size=70, min_samples=35)   # 或在目標群數區間內網格搜尋
names    = wordnet_hypernym(clusters)                     # 不叫模型命名
schema   = revise(schema, clusters)  →  重跑 pass2        # 迴圈

# 本研究（life_nodes.py、orse_label_exp.py）
TABLE = life_nodes.json          # 六類動詞表＝種子（研究者的概念工作）∪ 搭配（語料 lift，零標注）
for span in spans:
    verbs    = CKIP(span).verbs
    標法_程式 = {cls for v in verbs for cls in TABLE.get(v, ())}   # 一個動詞可落多類，不先中先得
    標法_模型 = span.第四欄                                       # 留存，不參與任何決定
    標法_歸納 = stem(verbs)                                       # 事後歸納；與手寫表 homogeneity 0.859
# 綱要不回頭改；手寫 193 個動詞裡 56 個從未出現在跨距，這個數字留著當方法的邊界

4.7 品味與評價

差異類型：資料與表徵。

  • MeDoraH：述詞聚類裡「信念與評價」自成一群。
  • 本研究：六類之一「品味與依附」，但 28 個動詞有 20 個從未出現在跨距；品味不長在兩點跨距上。
  • 判斷：先例，goût 獨立成類的旁證（證據：vlachidis §8(4)；orse_label/report.md）。

4.8 人在迴圈的位置

差異類型：管線設計。

  • 本研究：事前。研究者設計每一題的選項與話術，批次親跑；人工名冊只在評估時進場。

4.9 模型與部署

差異類型：其他（部署）。

4.10 信心

差異類型：邏輯判斷。

  • MeDoraH：抽取信心來自三組態投票（第 10 頁「confirmed — 0 of 3 refute votes」，程式訊號，計票規則未載明）；certainty_level 由模型判（講述者的確定度）；Reference 層的 0.97 來源未明。
  • 本研究：證據等級與切點支持度由程式從重複呼叫推導；跨距逐字驗證；五訊號設計。絕不叫模型自評。
  • 判斷：先例（投票同構）＋對照（模型判 certainty 不借）（證據：投影片第 10 頁；check_segment.py；WORKLOG 2026-09-06）。

4.11 單位與矛盾

4.13 評估

差異類型：邏輯判斷。

5. 三點判斷

  1. 核心主張相反。 對方讓模型先讀、再用結果修綱要（投影片第 21 頁「extraction as evaluation of the schema」）；本研究把綱要固定成程式查表、只讓模型選。兩者都成立，但回答的問題不同：對方問「綱要該長什麼樣」，本研究問「沒有標準答案時，哪些判斷能交給模型而不失去可驗證性」。
  2. 交會點在動詞。 海報右下第二個未決事項「動詞決定箭頭，中文關係動詞如何分類（分群）」，正是對方方法的中心（predicate clustering → candidate templates to accept or reject，第 13 頁）。這是最值得互相參照的地方，也是 09 第 ③ 件工作的由來；4.6 的參數（UMAP 50 維、HDBSCAN 70／35）是重寫時的起點。
  3. 投票同構，但多一層。 對方的三組態投票與本研究的證據等級是同一種程式化訊號，可引為同行做法；但對方另外讓模型判 certainty，本研究依紅線 2 不做。寫作時兩件事要分開講。

6. 與五條紅線的相容性

紅線 相容性 說明
1 不做人工配對式 gold standard 相容，理由不同 對方是根本沒有評估基準，本研究是刻意選擇免標準答案訊號；不能混為一談
2 不叫 LLM 自評信心 部分相容 對方的抽取信心靠投票（相容），但 certainty_level 由模型判（不相容）
3 每筆強制出處 方向一致、落實不足 對方出處在介面層與 JSON 欄位、無時間碼、共指改寫原文
4 推理可追溯 不相容 對方的中間產物只有示範 JSON，提示詞與投票紀錄未公開
5 抽取端零標注 對方整條線屬「含人工標注」 第二趟把本體注入抽取；本研究零標注線沒有對應物
