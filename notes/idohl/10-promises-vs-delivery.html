查證日期：2026-10-13。起因是追問「他們承諾卻沒做到的，論文裡真的沒有其他線索嗎」。答案是線索有，但最直接的不在論文，在 UKRI 的成果登錄。 方法：UKRI Gateway to Research（GtR）API 讀計畫 AH/Y007557/1 的全部成果紀錄（原始 JSON 快照存在 sources/gtr_AH-Y007557-1_2026-10-13.json）；GitHub 以 gh api 與轉址測試；idohl.org 以 curl；UCL Discovery 的 PDF 直接下載；兩場 YouTube 演講以自動字幕讀過。 體例：中立報導體。表格的「實況」欄只寫查得到的檔案與狀態，判斷另起一欄。

0. 給週會的三句話

  1. 對經費單位的自評比網站說得更滿：五項軟體全部登記「已開源」、八項資料庫與模型登記「已提供他人」、關鍵發現寫「ontology released stable version」「open access to datasets」；GitHub 上對得到的是一個 V0.2 原型本體、四支後處理腳本、安裝檔，與零個資料集。
  2. 他們有 ground truth，沒有公開：人工標注的「集體記憶、互為主體性、身分展演」基準資料登記為 providedToOthers: False；MDOH 的 ASR 與笑聲偵測也有人工校正的 ground truth 與自建的轉錄編輯器，演講說「希望釋出」，至今沒有。
  3. 對本研究的用法：related work 引用 GtR 原文對照 GitHub 實況，只陳述登記狀態與可查到的檔案，不下評語；本研究每次模型呼叫落檔進 git 這件事，在這個對照下才顯出分量。

1. 來源是什麼，為什麼有分量

UKRI 要求受資助計畫每年透過 Researchfish 回報成果，公開在 Gateway to Research。每條成果由計畫主持人自己填寫，欄位包括 softwareOpenSourced（軟體是否開源）、providedToOthers（是否已提供他人）、yearFirstProvided（首次提供年份）與自由文字的描述與影響。它是承諾的正本：措辭是計畫自己選的，狀態是計畫自己勾的。MeDoraH 的登錄有 5 項軟體與技術產品、8 項研究資料庫與模型、1 項研究材料、1 條關鍵發現、1 條影響摘要、9 筆出版品、6 筆合作、11 筆傳播。

來源：https://gtr.ukri.org/projects?ref=AH%2FY007557%2F1 ；API https://gtr.ukri.org/gtr/api/projects/10F2A066-994E-4626-A909-766A3F196307

5. 怎麼用

  • 寫 related work 時，引 GtR 的原文（登記狀態、年份、用語）與 GitHub 的檔案清單並列，不加評語；讀者自己會對出落差。
  • 不要寫成「他們沒做」。登記的是「已提供」，查到的是「只有二進位」或「只有 README」；兩者並陳即可。
  • 本研究可以對照著說的三件事：每次模型呼叫的 calls.jsonl 進 git；句層出處含時間碼；信心由程式訊號推導。這三件事在對方的自評裡都有對應的承諾（provenance tracking、evidential grounding、reproducible research），差別在能不能被第三方檢視。
