IDOHL GitHub 工具清單與本專案的關聯性

來源 extract_ohistory/refs/notes/idohl/05_工具清單與關聯性_2026-10-13.md　來源最後修改 2026-10-13　分類 ④ 口述歷史與數位人文　問題 ④

調查日期：2026-10-13（複查 2026-10-05 的調查，見 03_開源釋出與程式碼.md） 對象：IDOHL（International Digital Oral History Lab）開源釋出頁 https://idohl.org/OpenSource-Release 所連的 GitHub 儲存庫 方法：gh api 讀取兩個帳號的儲存庫清單、pushed_at、release 與 IDOHL-updator 的檔案樹；curl 檢查開源頁的連結。未 clone、未執行任何對方程式。關聯性判斷依據 03 筆記逐檔讀過的內容、refs/notes/vlachidis_medorah-ontology-memory-recollection.md 第 8 節，以及本專案 2026-09-10 的架構審查（plans/2026-09-10_表徵審查_宣稱事件中心.md）。 報告體例：中立報導體；每條事實附來源；查不到的寫「儲存庫未載明」。

1. 結論

這套 GitHub 對本專案的價值在表徵設計的先例與對照組，不在可執行的工具。六個儲存庫裡能跑的程式只有四支純 Python 後處理；六個都沒有 LICENSE，法律上只能重寫、不能取用。最接近的同類計畫是 MeDoraH，它的 LLM 抽取封在 NarraGraph 二進位檔裡，所以能比的是結果與資料結構，不是方法。

3. 工具清單（六個儲存庫，開源頁宣稱五個）

實驗室帳號 International-Digital-Oral-History-Lab

儲存庫 是什麼 可執行？
IDOHL-updator 網站 Updates 頁的新聞聚合器。Node 20＋cheerio，GitHub Actions 每週一、四 06:15 UTC 抓 UCL Information Studies 新聞（HTML 爬取）與 TU Darmstadt HDSM 部落格的 digital_oral_history_lab 分類（RSS），寫 landing_page/data/news-cache.json 供 Omeka S 頁面讀取。9 個檔案 可，但與口述歷史研究無關

4. 逐項關聯判斷

項目 與本專案的關聯 判斷
IDOHL-updator 無 無關
MDOH_Project 主旨是笑聲、遲疑等副語言事件，與本專案「證詞的多重樣貌是證據層次、不是待清理的雜訊」同立場；我們的 SRT 有時間碼可回到音訊，對方尚無實作 概念對照，無物可借
MeDoraH_Project README 的成果分類法（技術基礎設施／研究工具與資料集／出版品／資料集／方法）可當本專案整理對外釋出清單的骨架；要避免把預定成果寫成已釋出 低
NLP／Preprocessing 本專案的斷句線已有證據等級、切點支持度、講述者、時間碼，逐字合規 100% 我方已超過
NLP／Dashboard 結構模式統計與 orse_label_exp.py 的歸納動詞表互補；本專案有 data/entity_stage2_typed.csv 的七類型別，可以直接算「型別對 × 述詞」 可借想法，幾十行重寫
NLP／Network build_network.py 已有 PageRank／HITS／reciprocity，每邊帶出處、來歷、年代 我方已有
NLP／Clustering 正是三種任務設定裡的 ORC（Open Relation Clustering，開放關係聚類）。對方用 WordNet 上位詞命名群，是程式查表、不叫模型命名，與紅線 2、4 相容。中文可換成中研院語言所的中文詞網（Chinese WordNet） 可借方法；對方程式跑不起來，要自己寫
NarraGraph 黑盒。功能清單裡的「虛無模型」點出本專案的缺口：network/orse/ 的 reciprocity 0.0496／0.0661 沒有虛無基準，無法說是否高於隨機 黑盒；虛無模型值得補
NLP／資料 語料不可比（英語、無時間碼、受訪者是數位人文學者）；知態立場四欄詞表（claim_type／certainty_level／temporal_grounding／attribution_type＋is_negated）可直接參照，特別是 attribution_type 把 direct_quote、indirect_report、general_attribution 分開，對應本專案的六種來歷 詞表可借，資料不可比；對方四欄由模型判定，我們只借詞表、不借做法
Ontology／內容層 明文把 Claim 層排除在本體之外，說它屬於 RDF-star 或陳述節點；與 2026-09-10 審查定的 Speaker → Claim → Event → participants 同向。「先抽到粗層 hasSocioInstitutionalRelationWith，證據累積後再細化成 studiedAt」對應 life_nodes.py 六類的兩層結構 設計先例可引
Ontology／檔案層 SpeechSegment（startTime／endTime／speaker／audioFileReference）是 SRT 單位最自然的 RDF 落點；對方沒有連到內容層的屬性，本專案若輸出 RDF，補那一條連結就是貢獻 條件性可用
Ontology／中繼資料詞彙 描述 314 個 SRT 與北流人物頁的來源層時有用 低
Ontology／Palladio 手工編碼 關係型別只有數字、無對照表 無

5. 四件值得動手的事（待排程、未做；都是純程式、不呼叫模型）

  1. 型別對 × 述詞的結構模式表。 讀 output/experiments/orse_label/ 的跨距與名冊七類型別，算「人→作品」「人→機構」「人→人」各自的述詞分布與基數（1:1、1:N、N:1）。這是對方 generate_report_modern.py 做的事；本專案的材料多一層型別來源（TypeSource）可標注。
  2. reciprocity 與 PageRank 的虛無模型。 對 output/experiments/network/orse/ 兩個跨距口徑各跑配置模型（保留度數序列的隨機重連）數百次，報 z 分數與區間。沒有這一步，「reciprocity 0.05」只是一個數字。
  3. 述詞嵌入分群當六類的漏洞檢查。 用 CKIP 詞向量對跨距動詞分群，群名查中文詞網上位詞，看六類之外浮現什麼。對方在英語語料上浮現「信念與評價」自成一群，是 goût 獨立成類的旁證；本專案的對照會回答「品味與依附類 28 個動詞有 20 個從未出現」是詞表問題還是語料問題。
  4. 一個可比的跨語料數字。 對方合併檔（Combined_Interviews.json）裡 PERSON 主詞不是講述者本人的佔 42.8%（282／659）；本專案海報報 67.4% 他述，但定義不同（邊的 來歷 是講述者是否為端點）。用對方的定義在 ORSE 邊上重算一次，是目前唯一能與同行並列的數字。

6. 不該借的

  • certainty_level 由模型判定（紅線 2：絕不叫 LLM 自評信心）。
  • 把「我」改寫成人名（對方主詞代名詞 0 筆）。本專案只對映不改寫，出處鏈條靠原文字元座標。
  • 模型自由命名型別（單卷 160 種實體型別、436 種關係標籤）。本專案分類由程式查表。
  • 為了共指乾淨而排除轉述。與最終目標的硬約束 1「他述是主要材料」正面衝突；許石卷 139 句全是子女與劉福助的他述，照對方前處理會被清空。
  • 本體注入抽取。只能在「含人工標注」線（紅線 5），零標注線沒有對應物。

7. 寫作時的位置

MeDoraH 是最接近的同行，但它的釋出可檢視結果、不能重跑抽取：九個 release tag 指同一 commit、提示詞與模型未公開、評估只有 precision 性質的 1,429 筆人工回讀 91.3% warranted、無 recall、無 gold standard。本專案每次呼叫的 calls.jsonl 進 git、句層出處含時間碼、信心由程式訊號推導，這三點可以用對方的公開紀錄逐條證明是差異。中研院博士後計畫書與下一篇論文的 related work 都用得上。不能反過來拿 MeDoraH 當「口述歷史知識圖譜可行」的支持證據，對方給不出任何比率。

8. 保留

  • 對方的 Event 是有名字的事件（Project、Conference、Activity），本專案語料裡的事件多半沒有名字，只有「退伍之後」「那時候在××」。對方的本體可當分層先例，不能當事件層的模板。
  • ICCCM 2026 海報的目的是「找同路人」，IDOHL 是最明顯的一個；IDOHL-updator 的機器人每週仍在提交，帳號活著。是否聯繫 Jiajie Zhang 或 Andreas Vlachidis 由使用者決定。
